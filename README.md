# 数据校验代码重构（Python 3，仅标准库）

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `legacy_validator.py` | 重构前：15 个字段逐个 if 分支，作为差分测试的对照基准 |
| `validator.py` | 重构后引擎：规则自检 + 编译一次复用多次的统一校验循环 |
| `rules_full.py` | **规则表（唯一维护位置）**：与旧代码逐条等价的规则声明 + 字段登记表 |
| `conflict_demo.py` | 规则冲突检测样例（互斥规则 / 未知字段 / 参数越界 / 重复规则） |
| `test_differential.py` | 差分测试 + 自检单元测试 |
| `bench.py` | 性能基准：16 → 10000 条规则的扩展性实测 |

## 运行命令

```bash
python3 test_differential.py   # 差分测试（重构等价性证明）
python3 conflict_demo.py       # 规则冲突检测样例
python3 bench.py               # 性能数据
```

## 设计要点

- **规则即数据**：每条规则声明 `field / check / param / code / msg`，
  错误分类与消息语义完全由规则自带，引擎只做执行，语义与旧代码一致。
- **加载时自检**（`validator.check_rules`）：未知字段、参数越界
  （负数长度、非法类型、无法编译的正则等）、同字段互斥规则
  （min_length > max_length、min > max、枚举全部落在范围外、完全重复），
  全部在 `CompiledRuleSet` 构造时报 `RuleSetError`，并指出规则序号。
- **编译一次、复用多次**：构造时完成自检、按字段分组、预编译正则；
  `validate()` 对每条记录只查表执行，不做任何重复编译。

## 差分测试（等价性证明）

1. **固定规则 vs 旧代码**：随机种子生成 5000 条记录（合法/边界/非法/错误类型/
   缺字段混合），`legacy_validator` 与 `CompiledRuleSet` 的错误列表逐条相等；
   另覆盖全合法、全缺失、全错误类型三种极端记录。
2. **随机规则 vs 朴素解释器**：随机生成 500 组规则表 × 20 条记录，
   编译执行结果与不做任何预处理的 `naive_validate` 逐条一致，
   证明“编译一次”的优化不改变语义。

## 性能实测（本机 Python 3.12）

| 规则数 | 编译一次 | A: 编译后单条记录 | B: 每条重新编译 | C: 朴素逐条解释 | A 吞吐 |
| --- | --- | --- | --- | --- | --- |
| 16 | 0.20 ms | 1.7 µs | 15.2 µs | 4.1 µs | ~57 万条/秒 |
| 100 | 0.18 ms | 9.4 µs | 76.3 µs | 20.6 µs | ~10.6 万条/秒 |
| 1000 | 0.99 ms | 88.4 µs | 710.0 µs | 183.4 µs | ~1.1 万条/秒 |
| 10000 | 8.20 ms | 1015.7 µs | 过慢（分钟级） | 过慢（分钟级） | ~985 条/秒 |

结论：单条记录耗时随规则数近似线性增长（规则 ×10 → 耗时 ×9~11），
编译成本一次性且很小（1 万条规则 8.2 ms）；把编译放进每条记录的循环
（B 列）在 1 万条规则下不可行。

## 以后新增字段或规则，唯一改动位置

**只改 `rules_full.py`**：

- 新增字段 → 在 `SCHEMA` 登记字段名 + 在 `RULES` 追加规则；
- 新增/修改/删除规则 → 只改 `RULES` 列表；
- 引擎 `validator.py` 与旧基准 `legacy_validator.py` 都不需要动
  （只有引入全新校验类型时才需要扩展引擎的 `CHECK_TYPES` 与执行分支）。
